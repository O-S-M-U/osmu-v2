# TASK 0.1A — 기준 문서 식별·해시·우선순위 기록

## 목적

MODULE_SPEC 전수 추적을 시작하기 전에 어떤 파일이 기준선인지 기계적으로 다시 확인하고, 이후 작업자가 같은 revision을 사용하도록 단일 기준선 문서를 만든다.

## 시간과 모델

| 항목 | 값 |
|---|---|
| 제한 시간 | 60분 |
| 예상 토큰 | 10K–15K |
| 추천 모델 | GPT-5.6 Terra |
| Thinking effort | Medium |
| 담당자 | 작업자 A / yurim-agent |
| 브랜치 | `agent/yurim/0.1a-baseline-lock` |

50분이 지나면 새 조사를 시작하지 않는다. 남은 10분 동안 현재 결과, 검증, 미결 사항과 다음 시작점을 저장한다.

## 입력

- `docs/IMPORT_MANIFEST.json`
- `docs/baseline/MODULE_SPEC_20260522_v23.md`
- `docs/baseline/워크플로우_시각화_20260522_v19.html`
- `AGENTS.md`
- `.agent/project.md`

입력 기준 문서는 읽기 전용이다.

## 산출물

`docs/requirements/BASELINE.md`를 만들고 다음을 기록한다.

1. 두 기준 파일의 경로, 문서 버전, 문서 날짜, 파일 크기와 SHA-256
2. `IMPORT_MANIFEST.json`에 기록된 해시와 현재 파일 해시의 일치 여부
3. MODULE_SPEC와 워크플로우가 최우선 기준이며, 두 문서가 충돌하면 임의 해석하지 않고 `decision_required`로 올린다는 규칙
4. 기준 사본은 수정하지 않고 승인된 변경은 새 버전과 결정 기록으로 남긴다는 규칙
5. 후속 작업 `0.1B`와 `0.2`가 시작할 정확한 위치

## 통과 기준

- [ ] 기준 문서 2개의 SHA-256을 실제로 다시 계산했다.
- [ ] manifest와 비교 결과가 명시돼 있다.
- [ ] 기준 문서 원본을 변경하지 않았다.
- [ ] 충돌 및 변경 처리 규칙이 기존 프로젝트 계약과 일치한다.
- [ ] `docs/progress/20260910.md`에 결과와 다음 시작점을 남겼다.
- [ ] 작업 보드에서 `0.1A`의 상태와 evidence를 갱신했다.
- [ ] 변경 사항을 검사하고 commit했다.
