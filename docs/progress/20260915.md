### 검사와 증거

- 변경 범위: `git diff --name-only 357adfea34226f3141d7bb17a70daf629ad95660 --`로 허용된 세 경로만 변경됐는지 확인한다.
- 읽기 전용 보존: `git diff --exit-code 357adfea34226f3141d7bb17a70daf629ad95660 -- docs/baseline docs/decisions .agent`로 변경이 없음을 확인한다.
- 기준 해시: PowerShell `Get-FileHash -Algorithm SHA256`과 `(Get-Item -LiteralPath ...).Length`를 사용해 두 기준 파일의 SHA-256과 크기를 `docs/requirements/BASELINE.md`의 값과 대조한다.
- 절차 항목: `Select-String`으로 제안본, 결정 기록, 승인 게이트, 기준선 교체, 이전 기준선 보존, `decision_required` 문구를 확인한다.
- YAML 구문: 설치된 Python과 PyYAML을 사용할 수 있으면 `yaml.safe_load`로 작업 보드를 파싱한다. 사용할 수 없으면 PowerShell에서 Task 0.1B 필수 필드를 직접 확인하고 그 제한을 기록한다.
- 줄바꿈: checkout의 문서는 CRLF이며 Windows PowerShell의 `Set-Content`가 전체 파일 인코딩·줄바꿈을 바꿀 수 있으므로 패치 단위로 편집했다. Git의 줄바꿈 경고 여부와 diff를 함께 확인한다.
- Usage: 작업 전후 확인 가능한 Codex 주간 창은 모두 2% 사용(98% 잔여)으로 표시되어, UI 정수 백분율 기준 변화는 0%p였다.

검사 결과:

- 변경 경로는 `docs/requirements/BASELINE.md`, `docs/progress/20260915.md`, `project/TASK_BOARD.yaml` 세 개이며 모두 허용 범위 안이다.
- `docs/baseline/**`, `docs/decisions/**`, `.agent/**`의 기준 revision 대비 diff는 없었다.
- Windows checkout의 두 기준 파일은 CRLF 변환으로 각각 96,244 bytes/`18a462be...`, 88,939 bytes/`94880e06...`로 보였다. Git blob 원시 바이트를 Python `subprocess.check_output`과 `hashlib.sha256`으로 검사한 결과는 각각 94,946 bytes/`70b72bdc...`, 87,841 bytes/`d756c45e...`로 기준표와 일치했다.
- 두 번째 한글 파일 경로는 Python 결과를 Windows 콘솔에 출력할 때 글자가 깨졌지만, 전달한 경로와 계산된 크기·해시는 정확했다. PowerShell의 `-LiteralPath` 검사에서는 경로가 정상 표시됐다.
