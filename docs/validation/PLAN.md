# 최소 검증 계획

## 공통 샘플

fixtures/sample.json은 프로젝트 내부에서 만든 기능 확인용 글이다. 외부 사실·가격·통계·라이선스 이미지에 의존하지 않는다. 제목·소제목·문단·목록·링크·이미지·캡션의 보존을 확인한다. 품질 검사기의 1500자 기준을 통과시키기 위한 발행 원고는 아니다.

## 플랫폼별 순서

1. 대상 블로그·계정과 허용 작업 범위 확인.
2. 로그인/API 연결 상태와 실제 대상 일치 확인.
3. 샘플 제목과 블록·이미지 입력.
4. 초안 저장 후 편집기를 나갔다가 다시 열어 누락·배치·링크 확인.
5. PC·모바일 표현을 원본과 비교.
6. 공개 발행/예약 검증을 요청받은 경우에만 진행하고 플랫폼의 실제 목록·URL을 다시 확인.

티스토리: 이전 테스트의 HTML 모드 입력 부분을 참고한다.
워드프레스: WordPress.com/자체 호스팅 구분과 인증·REST 지원부터 확인한다.
네이버: 블록 조립 및 이미지 업로드 방식을 실제 SmartEditor에서 확인한다. HTML 직접 삽입을 가정하지 않는다.
Slack: 승인된 테스트 채널에 내용 전송→같은 메시지 수정→다시 읽기. 사용자 버튼 액션과 콘텐츠 수정은 후속 실험으로 분리한다.

## 통과 조건

제목·본문 순서·이미지 위치·링크가 재열기 후 유지되고 증거가 있어야 초안 저장 검증 통과다. 단순 클릭/전송 성공은 통과가 아니다. 결과가 애매하면 확인대기로 남기며 중복 재시도하지 않는다.

## 기록 형식

날짜 / 담당 / 대상 / revision / 실행 범위 / 실제 결과 / 증거 파일 또는 URL / 통과·실패·확인대기 / 다음 단계.
