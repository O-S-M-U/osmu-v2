## 기준 우선순위

1. `MODULE_SPEC_20260522_v23.md`와 `워크플로우_시각화_20260522_v19.html`을 O.S.M.U v2 작업의 최우선 기준 문서로 사용한다.
2. 사용자가 승인한 `docs/decisions/` 기록은 기준 문서의 승인된 변경 근거로 사용한다. `docs/reviews/`는 제안이며 그 자체로 확정 명세가 아니다.
3. 두 최우선 기준 문서가 충돌하면 어느 한쪽을 임의로 선택하거나 해석하지 않는다. 관련 작업을 `decision_required`로 올리고 사용자 승인 결정 기록이 생길 때까지 해당 구현을 멈춘다.

## 충돌과 변경 처리 규칙

- `docs/baseline/`의 기준 사본은 읽기 전용이며 직접 수정하지 않는다.
- 승인된 변경은 새 버전의 명세 또는 워크플로우 파일로 만들고, 변경 근거와 승인 내용을 `docs/decisions/`에 남긴다.
- 새 버전이 승인되기 전까지 위 표의 경로와 SHA-256 조합을 동일 revision의 기준선으로 사용한다.
- 기준선 확인, 코드 존재, 로컬 검증, 외부 서비스 검증, 공개 발행 완료는 서로 다른 상태로 기록한다.

## 후속 작업의 정확한 시작점

### 0.1B — 버전 변경·결정 절차 확정

- 선행 입력: 이 문서의 `## 충돌과 변경 처리 규칙`과 `docs/decisions/20260909.md`의 `## 미결`.
- 시작 위치: `docs/requirements/BASELINE.md`의 `## 충돌과 변경 처리 규칙` 바로 아래에서 새 버전 생성, 승인 결정 연결, 기준선 교체 및 이전 기준선 보존 절차를 구체화한다.
- 경계: 기준 사본은 수정하지 않으며, 절차에 명세 판단이 필요하면 별도 결정 기록을 만들고 `decision_required`로 둔다.

### 0.2 — MODULE_SPEC 전 요구사항 원자화

- 시작 조건: `0.1B`가 검토를 통과해 상위 작업 `0.1`의 의존성이 해소된 뒤 시작한다.
- 원문 시작 위치: 고정 해시의 `docs/baseline/MODULE_SPEC_20260522_v23.md`에서 `## 0. 개요 (Overview)`(현재 파일 10행)부터 문서 순서대로 읽는다.
- 기록 시작 위치: `docs/requirements/TRACEABILITY.md`의 `## 추적표` 아래 예시 행을 첫 실제 Requirement ID 행으로 교체한다.
- 추출 범위: 제목 요약이 아니라 입력, 출력, 내부 로직, DB 갱신 시점, 오류·fallback, 정책 게이트, 오픈 이슈를 포함해 `## 9. 변경 이력 (Changelog)`까지 전수 확인한다. 원문 충돌이나 모호성은 원자화 과정에서 결정하지 않고 `decision_required`로 기록한다.
